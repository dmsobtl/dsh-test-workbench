# Skill: 视觉回归测试

## 触发条件

当用户要求对比 UI 变化、检查视觉回归、验证页面样式一致性时使用。

## 工作流程

### 首次建立基线

1. `app_launch` 打开目标页面
2. 等待页面完全加载（网络空闲）
3. `app_screenshot` 保存为基线，命名规则：`{页面名}-{视口}`
4. 记录基线建立时间和环境

### 回归对比

1. `app_launch` 打开目标页面
2. `app_screenshot_diff` 对比基线
3. 分析结果：
   - matchPercent >= 99%：通过
   - 95% <= matchPercent < 99%：警告，可能是预期变更
   - matchPercent < 95%：失败，需要人工确认

### 多页面批量对比

对每个页面重复上述流程，汇总结果为表格：

| 页面 | 匹配率 | 状态 | 备注 |
|------|--------|------|------|
| 首页 | 99.2% | ✓ | |
| 登录 | 87.3% | ✗ | 新增横幅 |

## 基线管理

- 基线存储在 `./baselines/` 目录
- 确认是预期变更后，用 `app_screenshot saveAs` 更新基线
- 建议将 baselines 目录纳入 git 管理

## 注意事项

- 动态内容（时间、广告）会导致误报，检查 diff 区域是否在动态区
- 不同分辨率的截图无法对比，确保 viewport 一致
- 字体渲染在不同 OS 上可能有差异，建议固定在同一环境跑
